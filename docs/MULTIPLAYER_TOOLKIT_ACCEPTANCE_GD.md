# Multiplayer Toolkit G/D Acceptance Criteria

状态：Draft
适用基线：BetterCoop `v0.5.0` / protocol 5
范围：仅定义 G1–G12 与 D1–D10 的可验收行为，不代表这些功能已经实现。

## 全局验收边界

- 所有功能只能观察、比较、提示、导出或生成测试计划；不得自动修改、下载、删除、替换、启停其他 Mod，不得强制准备、结束回合、跳过选择、注入动作、修复分歧、回滚或改写游戏状态、RNG、存档。
- 允许写入的持久数据仅限 BetterCoop 自己的 lockfile、sidecar、报告历史和会话标记；写入失败不得损坏或阻止游戏本体保存，且必须显式降级。
- 诊断结论只使用三级置信度：`已确认`、`高度疑似`、`证据不足`。只有结构化游戏错误、精确包比较或明确异常归属可以标为 `已确认`；时间接近、共享补丁目标或无进展计时不得单独证明责任方。
- 对端提供的名称、版本、能力、状态和报告均视为不可信输入；必须限长、限数、验证编码、移除控制字符，并拒绝未知或畸形结构。
- 不发送或导出文件内容、设置值、绝对路径、存档内容、Steam ID、IP/中继地址、凭据、剪贴板内容或原始日志。包和设置只交换或导出规范化标识及摘要。
- 不自动上传遥测、报告或规则查询。任何跨玩家诊断共享都必须在同一已认证会话内、使用固定上限；报告落盘或复制必须由玩家明确触发。
- 显示玩家等待或选择状态时，只能展示游戏已授权该观察者获知的状态；不得泄露手牌、牌组、遗物、事件选择、路线、隐藏意图、种子或 RNG 状态。
- 只有 Guard 域的强制兼容能力缺失或校验内部错误必须在开局前失败闭锁；纯显示/
  Diagnostics 能力缺失只能降级为“不可用”，不得削弱现有包指纹、游戏版本和
  原生状态校验。

## G1 不匹配修复表

- **用户可观察行为：** Mod 不匹配时显示表格，逐项区分“仅本机存在”“仅主机存在”“同 ID 内容或版本不同”“仅整体指纹不同”；每行显示 Mod ID、差异方向、置信度和只读修复建议。
- **成功标准：** 精确复用 protocol 5 的逐 Mod 差异；相同 ID 在双方各出现一个不同摘要时合并为一行；无法定位单个 Mod 时明确显示加载顺序或全局组成差异，不猜测责任 Mod。
- **降级/失败行为：** 对端没有逐 Mod 能力、条目畸形或超过上限时，只显示安全的整体不匹配结论；解析错误不得隐藏原生 `ModMismatch` 或允许继续。
- **安全与隐私边界：** 不显示摘要、路径或文件名；对端 Mod ID 必须清理控制字符并限制为 100 个显示字符；表格不提供自动修复按钮。
- **量化指标：** 最多接受 256 个差异条目；在参考机器上解析和构表 P95 不超过 20 ms；超过 100 行时保留总数并分页或虚拟化，不截断安全结论。
- **AT-G01-01（正常）：** 双方 `ExampleMod` ID 相同、摘要不同；弹窗只生成一行“内容或版本不同：ExampleMod”，置信度为“已确认”，且不存在 64 位摘要文本。
- **AT-G01-02（异常）：** 对端发送超长、含控制字符和畸形编码的条目；无 UI 注入、崩溃或摘要泄露，畸形项被拒绝，原生不匹配仍保持阻断。

## G2 复制修复清单

- **用户可观察行为：** G1 页面提供“复制修复清单”，生成适合发给队友的精简文本，按本机、主机和双方共同操作分组。
- **成功标准：** 清单包含错误编号、游戏/BetterCoop 版本、差异 Mod、方向、置信度及退出重启建议；内容与当前 G1 表格一致。
- **降级/失败行为：** 剪贴板不可用时显示非阻塞失败提示并保留页面；没有安全可显示的单项差异时复制整体差异说明。
- **安全与隐私边界：** 复制前复用报告脱敏；不得包含包摘要、路径、Steam ID、IP、凭据或原始日志；不得自动发送消息或打开外部链接。
- **量化指标：** 输出不超过 16 KiB；最多列出 100 个 Mod，余项以计数表示；生成 P95 不超过 20 ms。
- **AT-G02-01（正常）：** 存在本机独有、主机独有和同 ID 不同内容三类差异；复制文本分组正确、方向正确、无重复项。
- **AT-G02-02（异常）：** 系统剪贴板调用抛出异常；游戏和弹窗继续可用，显示“复制失败”，日志中不写入待复制全文。

## G3 本地 Mod Doctor

- **用户可观察行为：** 本地检查页列出重复 manifest ID、旧版残留、缺失或禁用依赖、无效版本约束、加载失败、声明文件缺失及本地/Workshop 覆盖关系。
- **成功标准：** 结论来自本机 manifest、ModManager 状态和已加载程序集；每项给出证据、置信度和手动处理建议。
- **降级/失败行为：** 文件不可读、manifest 未知字段或依赖图不完整时标为“证据不足/无法检查”；不得把未检查当作通过。
- **安全与隐私边界：** 只读扫描；不启停、移动、删除或重装 Mod；UI 可显示本地来源类别和相对包名，但复制报告仍不得包含绝对路径。
- **量化指标：** 对 256 个 Mod、4096 个包文件的元数据检查 P95 不超过 500 ms；单项证据最多 1 KiB；扫描期间不读取无关用户目录。
- **AT-G03-01（正常）：** `FeatureMod` 依赖 `LibraryMod >= 2.0`，本机只有 1.5；Doctor 准确显示依赖版本不足、相关两项 ID 和“已确认”。
- **AT-G03-02（异常）：** 两个 manifest 形成依赖环且其中一个 JSON 损坏；Doctor 不崩溃、不修改文件，分别显示依赖环和无法解析，并将总体状态标为未通过。

## G4 Workshop 更新观察器

- **用户可观察行为：** 游戏运行期间观察已加载 Workshop 包的本地元数据变化，显示“更新进行中”“文件已变化，需重启”或“观察不可用”。
- **成功标准：** 已加载包发生增删、长度或修改时间变化后，BetterCoop 在下一次观察周期内标记该 Mod，并保持现有 sticky restart-required 语义。
- **降级/失败行为：** Steam 元数据缺失、目录不可访问或更新状态不确定时显示“未知”，并由现有校验门在准备/重连时失败闭锁；不得声称更新完成。
- **安全与隐私边界：** 不调用订阅、取消订阅、下载、暂停、恢复或重启 Steam；不访问网络；不显示或导出 Workshop 绝对路径。
- **量化指标：** 菜单/大厅中最多每 5 秒轮询一次；单轮只做有界元数据检查，P95 不超过 25 ms；同一 Mod 的提示至少 30 秒去重。
- **AT-G04-01（正常）：** 已加载 Workshop Mod 的文件在菜单中变化；5 秒内显示该 Mod 需重启，随后准备操作被现有校验门阻止。
- **AT-G04-02（异常）：** Workshop 目录在扫描中暂时消失或拒绝访问；观察器显示未知/不可用，不触发自动下载，不把旧指纹继续标为健康。

## G5 环境 lockfile / 导出

- **用户可观察行为：** 玩家可预览并主动导出当前联机环境 lockfile，包含游戏构建、BetterCoop 协议/规则版本、有序 Mod ID/声明版本/包摘要、PCK 组摘要及 G10 设置摘要。
- **成功标准：** 对未变化环境重复导出得到相同的规范化环境摘要；重新导入能逐字段比较并指出差异类别。
- **降级/失败行为：** 捕获未完成、环境不健康或字段不可规范化时拒绝生成“已锁定”文件，允许导出带明确失败状态的诊断副本。
- **安全与隐私边界：** 必须由玩家点击导出；不包含文件内容、设置值、绝对路径、存档、账号或网络标识；导入文件按不可信数据解析且不执行其中内容。
- **量化指标：** 最多 256 个 Mod、每 Mod 8 个分类摘要、文件最大 512 KiB；从冻结指纹生成 P95 不超过 200 ms；模式版本必须显式记录。
- **AT-G05-01（正常）：** 同一环境导出两次并重新导入；规范化环境摘要相同，比较结果为“已确认一致”。
- **AT-G05-02（异常）：** lockfile 被截断、字段超限或模式版本未知；导入被拒绝并指出原因，不分配无界内存，也不把它当作匹配环境。

## G6 存档环境 sidecar 封印

- **用户可观察行为：** 原生保存成功后，BetterCoop 在自己的数据区域原子写入独立 sidecar，记录该存档对应的环境摘要、游戏构建、协议、时间和 sidecar 模式版本；UI 显示“已封印”或“未封印”。
- **成功标准：** sidecar 只在确认原生保存完成后产生；流式计算并保存精确存档
  内容 SHA-256 与长度，加载前重新验证，以此把记录与对应字节和 G5 环境关联；
  永不修改原生存档字节。
- **降级/失败行为：** 写入被拒绝、磁盘已满或进程中断时保留原生保存结果，显示“存档已保存但环境未封印”；临时 sidecar 不得冒充完整记录。
- **安全与隐私边界：** sidecar 不包含存档内容、文件绝对路径、账号信息或设置值；
  存档内容摘要不发送给 peer、不进入普通报告/剪贴板；不得嵌入、重写、移动、
  恢复或删除游戏存档。
- **量化指标：** sidecar 不超过 64 KiB；存档只读流式 hash 上限 64 MiB；使用
  临时文件加原子替换；原生保存完成后的附加 P95 延迟不超过 250 ms。
- **AT-G06-01（正常）：** 原生多人存档完成且环境健康；sidecar 原子生成，重新读取后环境摘要、模式版本和存档关联均正确，原生存档哈希未变化。
- **AT-G06-02（异常）：** sidecar 目录只读/写入中断，或 sidecar 被复制到另一份
  已改字节/改名存档；原生存档仍可加载且哈希不变，UI 显示未封印/绑定不匹配，
  残缺、陈旧或篡改记录不会被接受。

## G7 旧存档兼容警告

- **用户可观察行为：** 加载多人存档前比较 G6 sidecar 与当前环境；显示“环境一致”“环境不同”或“旧存档无封印，无法证明”。
- **成功标准：** 存档字节绑定与当前环境记录均匹配时显示“与本机当时记录的环境
  一致”；不使用“已证明兼容”。不匹配时按存档绑定、游戏构建、Mod 包、PCK、
  设置或协议分类列出差异，并在玩家进入加载大厅前提示。
- **降级/失败行为：** sidecar 缺失、损坏、版本未知或存档关联失败时只给“证据不足”警告；不得伪造兼容结论。
- **安全与隐私边界：** 功能只警告并允许玩家取消原生加载；不得修改、迁移、回滚或“修复”旧存档，也不得绕过当前全员包校验。
- **量化指标：** sidecar 与当前冻结环境比较 P95 不超过 200 ms；最多显示 100 个差异并保留总数；警告在任何开始运行消息前出现。
- **AT-G07-01（正常）：** 存档字节摘要/长度、sidecar 与当前环境记录完全一致；
  显示“与本机当时记录的环境一致（不等于兼容证明）”，随后仍执行现有玩家间校验。
- **AT-G07-02（异常）：** sidecar 缺失或环境摘要不同；显示对应“证据不足”或分类差异，不改写存档，不自动启停 Mod。

## G8 Harmony 冲突图

- **用户可观察行为：** 只读图表按目标方法展示 Harmony owner、prefix/postfix/transpiler/finalizer、优先级和 before/after 关系，并区分“共同目标”“顺序风险”“已观察到补丁失败”。
- **成功标准：** 图数据与运行时 Harmony patch metadata 一致；仅共同目标不能高于“高度疑似”，明确 patch 异常才可标为“已确认”。
- **降级/失败行为：** 某 owner 或方法无法解析时显示未知节点；图过大时聚合显示并允许按 Mod/方法筛选，不能阻止诊断页面其余部分。
- **安全与隐私边界：** 不 unpatch、不重排优先级、不重新执行补丁；清理 owner/方法显示字符串；复制结果不含程序集绝对路径。
- **量化指标：** 最多处理 5000 个 patch 记录；建图 P95 不超过 300 ms、额外内存不超过 8 MiB；单节点显示文本最多 200 字符。
- **AT-G08-01（正常）：** 两个测试 Mod patch 同一方法且声明相反顺序；图正确显示两 owner、patch 类型和顺序边，标为潜在顺序风险。
- **AT-G08-02（异常）：** owner 名含控制字符且一个目标反射失败；页面无注入或崩溃，未知节点被隔离，未执行任何 unpatch。

## G9 分类指纹

- **用户可观察行为：** 将每个 Mod 的差异只读分类为 manifest/依赖、程序集、PCK/内容、其他包文件和 G10 声明设置，同时保留严格整体指纹。
- **成功标准：** 分类摘要能指出差异类别；所有分类一致但整体摘要不同时仍报告
  全局/顺序差异；分类结果不得使当前严格校验变宽松。发布前必须证明本体原生
  Mod-list 在按远端 count/length 分配前执行单项和累计上限。
- **降级/失败行为：** 无法证明原生分配前限长时不得发布 G9 wire 扩展，继续使用
  protocol 5 逐 Mod/整体结论；对端类别未知或条目超限时同样退回，不把“无法分类”
  当作相同。
- **安全与隐私边界：** 网络和报告仅使用固定类别、Mod ID 和摘要；不发送相对文件名、文件内容、设置值或路径。
- **量化指标：** 每 Mod 最多 8 个固定类别，优先编码为每 Mod 一条分类向量；
  最多 256 个 Mod、总编码不超过 64 KiB；从冻结捕获构造 P95 不超过 20 ms，
  且必须通过原生十秒握手压力测试。
- **AT-G09-01（正常）：** 双方仅测试 Mod DLL 字节不同；表格显示“程序集类别不同”，严格整体不匹配仍阻断。
- **AT-G09-02（异常）：** 原生接收 fixture 提供恶意 count、单字符串 length 和累计
  近上限数据；在任何按远端值分配前拒绝，实际 allocated bytes 符合固定预算。
  未通过该审计的构建不启用 G9；未知类别仍退回 protocol 5，不泄露摘要。

## G10 确定性设置声明

- **用户可观察行为：** 选择加入该契约的 Mod 在自身包内提供固定声明文件，并通过
  F6 push-only API 发布影响确定性的设置摘要；BetterCoop 显示声明有效性及双方
  “设置摘要一致/不同”，不接收或显示实际值。
- **成功标准：** 声明文件受现有包指纹保护并只包含 provider ID/schema；合作 Mod
  的自身一致性测试证明语义相同值产生相同摘要、不同值产生不同摘要。声明存在时，
  摘要缺失、冲突、过期或 schema 不符使该声明 Mod 的联机校验失败闭锁；初始摘要
  随原生 Mod-list 冻结，冻结后不同摘要触发 sticky restart-required。
- **降级/失败行为：** 未加入契约的 Mod 显示“未声明”，不得因此声称其设置安全；未知声明版本拒绝使用，保留现有包指纹保护。
- **安全与隐私边界：** BetterCoop 只接受固定声明元数据和已经计算好的 32 字节摘要；
  拒绝绝对路径、`..`、设置键值、任意文件读取和回调/delegate 注册。API 不同步
  调用第三方代码。
- **量化指标：** 每 Mod 最多 64 个声明项，单项声明元数据最多 256 B，所有声明
  元数据不超过 64 KiB；摘要接收与冻结 P95 不超过 100 ms。
- **AT-G10-01（正常）：** 合作 Mod 的契约 fixture 在两端以不同枚举顺序表示语义
  相同设置并发布相同摘要；BetterCoop 接受摘要、判定一致，UI 和传输中均无原始值。
- **AT-G10-02（异常）：** 声明请求绝对路径/遍历父目录时被拒绝且未读取目标；另一个
  fixture 在指纹冻结后发布不同设置摘要时触发 restart-required，并在下一 Guard
  gate 失败闭锁，不静默改写已暴露摘要。

## G11 能力 / 协议协商

- **用户可观察行为：** Guard 兼容性仍由 STS2 原生 Mod-list 在加入前判定；进入
  lobby 后，独立 Diagnostics Protocol 显示每名玩家支持的纯可选 G/D/H/C/F
  能力。缺失能力显示“不支持”，而不是不健康。
- **成功标准：** Guard Protocol 和包不兼容仍按现有路径失败闭锁且不能被协商关闭；
  Diagnostics major/minor、feature bitset 和 Hello/ACK 仅决定可选控件是否显示，
  永远不参与 ready/start gate。
- **降级/失败行为：** 同一发布包内 Diagnostics 被关闭/初始化失败、未知能力、
  防御性注入的未知 major、重复/矛盾消息或协商超时，只禁用对应 peer 的可选
  功能并显示原因；不得断开、阻止 ready 或调用原生 `ModMismatch`。真正不同
  Guard 包会在此之前由原生 Mod-list 独立拒绝。
- **安全与隐私边界：** 必须验证当前会话成员，使用固定 schema、限长、限数、限频
  和最多三次 Hello 重试；不得携带任意 URL、自由文本或可执行数据。payload 只
  允许一层有界重复记录，先在 `ReadOnlySpan<byte>` 上验证 count、length、
  remaining bytes 和累计预算，再分配数组/字符串。不能证明“反序列化分配前
  限长”时，Release 必须禁用整个自定义通道。
- **量化指标：** 最多 64 个固定能力的位集，Hello/ACK payload 不超过 256 B；
  处理 P95 不超过 10 ms；超时后停止重试，不占用原生十秒握手预算。
- **AT-G11-01（正常）：** 双方 Guard 包相同，一方本地关闭可选 HUD；允许加入，
  协商后只把该端 HUD 标为不可用，Guard 状态不变。
- **AT-G11-02（异常）：** 当前 lobby peer 发送超限/未知 Diagnostics major，
  仅该 peer 的可选功能降级且原生联机继续；另一个 Guard 包版本不同的独立场景
  仍由原生 Mod-list 在加入前失败闭锁。

## G12 已知问题规则目录

- **用户可观察行为：** 本地规则目录按精确游戏构建、Mod ID/版本、异常签名或 Mod 组合显示已知问题、置信度、证据来源描述和已验证处理办法。
- **成功标准：** 规则只在所有必需键匹配时命中；每条规则含稳定 ID、模式版本、适用范围、置信度和至少一个正例及近似反例。
- **降级/失败行为：** 目录缺失、损坏、版本未知或规则冲突时显示目录不可用，不影响现有结构化校验；低置信度规则不得改变根因分类。
- **安全与隐私边界：** 初始范围仅使用随已验证 BetterCoop 包发布的本地目录，不联网更新、不执行规则内容、不基于社区黑名单自动修改或阻断；规则不能覆盖原生或指纹失败闭锁。
- **量化指标：** 5000 条规则、256 个 Mod 的匹配 P95 不超过 50 ms；单条规则显示文本不超过 2 KiB；每条规则必须有自动化正例与近似反例。
- **AT-G12-01（正常）：** 精确游戏构建、Mod 版本和 `MissingMethodException` 成员均匹配；显示对应规则和其既定置信度，近似版本不命中。
- **AT-G12-02（异常）：** 目录包含重复 ID、冲突规则或未知模式；整组冲突规则禁用并报告目录问题，不执行内容、不自动阻断联机。

## D1 软锁观察器

- **用户可观察行为：** 当游戏处于应继续推进的权威阶段、网络仍连接且长时间没有权威进度时，显示“疑似停滞”提示、持续时间和打开 D2/D3 的入口。
- **成功标准：** 只有明确 Softlock 异常可标“已确认”；无进展计时最多为“高度疑似”，正常暂停、菜单、加载、动画和已知玩家选择阶段不宣称软锁。
- **降级/失败行为：** 无法读取阶段或进度令牌时不启动计时，并显示观察不可用；观察器自身异常不得影响回合或网络处理。
- **安全与隐私边界：** 完全只读；不注入动作、不跳过动画/选择、不结束回合、不暂停或断开连接；不显示隐藏选择内容。
- **量化指标：** 默认在连续 90 秒无权威进度后 2 秒内提示；同类提示至少 60 秒去重；平均 CPU 低于 0.2%，每帧 P99 开销低于 0.2 ms。
- **AT-D01-01（正常）：** 测试流程停在需远端推进的阶段 90 秒且连接正常；提示“疑似停滞/高度疑似”，D3 记录触发依据。
- **AT-D01-02（异常）：** 玩家在合法选择界面思考超过 90 秒或游戏暂停；不得宣称软锁、不得操作游戏，最多显示 D2 的已确认等待原因。

## D2 等待原因置信度

- **用户可观察行为：** 控制台显示当前“等待网络、等待某玩家输入、等待主机消息、等待动画/动作队列、原因未知”，并紧邻显示置信度和证据摘要。
- **成功标准：** 原生权威状态直接指向原因时标“已确认”；只读
  `WaitForRemoteChoice` prefix/finalizer 观察属于 `NativeObserved`，最多“高度
  疑似”；两个以上其他独立信号一致时同样最多“高度疑似”；仅超时或日志相邻时
  为“证据不足”。
- **降级/失败行为：** 信号冲突时显示冲突证据和“证据不足”，不得选择一个方便的责任方；无数据时显示未知。
- **安全与隐私边界：** 只显示等待类别、经授权的玩家显示名和持续时间；不显示正在选择的卡牌、事件、路线或其他隐藏内容。
- **量化指标：** 状态变化后 250 ms 内刷新；最多保留 5 条证据；显示名限制 100 字符并清理控制字符。
- **AT-D02-01（正常）：** 已审计 prefix 观察到等待玩家 B 且 finalizer 尚未完成；
  显示“等待玩家 B 输入/高度疑似/NativeObserved”，不显示选择内容。移除 Hook
  后显示 Unknown，且测试证明没有主动调用 `WaitForRemoteChoice`。
- **AT-D02-02（异常）：** 网络延迟与本地动作队列同时异常且无法区分先后；显示两个候选证据和“证据不足”，不归责玩家或 Mod。

## D3 本地飞行记录器

- **用户可观察行为：** 本地时间线记录加入、握手、准备、开局、房间/回合阶段、公开选择状态、动作队列状态、连接转换和诊断触发；可随报告主动导出。
- **成功标准：** 事件使用单调时钟排序并具有固定类型；捕获失败只丢失该事件，不得改变原始调用时序或结果。
- **降级/失败行为：** 事件洪水时丢弃最旧记录并增加 dropped 计数；未知事件仅记录有界类别，不保存原始对象或消息载荷。
- **安全与隐私边界：** 默认仅在内存；不记录手牌/牌组/选择内容、种子、RNG、消息载荷、路径、账号或网络端点；只有玩家主动生成报告时经过脱敏导出。
- **量化指标：** 最多 1024 个事件或最近 15 分钟，取较小者；单项最多 512 B，
  包含对象/索引在内 retained memory 不超过 2 MiB；单次记录 P95 小于 0.5 ms。
- **AT-D03-01（正常）：** 完成一次加入、准备、开局和回合转换；时间线顺序正确、类型完整，导出中无隐藏游戏内容。
- **AT-D03-02（异常）：** 每秒注入 1000 个测试事件持续 10 秒；游戏继续响应，记录数保持上限，dropped 计数正确且无无界增长。

## D4 断线前网络快照

- **用户可观察行为：** 断线诊断显示断线前 60 秒的平滑 RTT、丢包估计、距最后
  收包时间、远端加载状态和原生连接状态转换，并注明不可用字段。
- **成功标准：** 指标只来自已审计的 `PingMsec`、`PacketLoss`、
  `LastReceivedTime`、`RemoteIsLoading` 和原生连接事件；时间窗与 D3 对齐；
  Timeout 与 StateDivergence 等结构化原因仍分别分类。
- **降级/失败行为：** 平台不提供某项指标时显示“不可用”，不填零、不伪造健康分数；采样异常不得触发断线。
- **安全与隐私边界：** 不记录或显示 IP、端口、Steam ID、中继节点 ID、票据或数据包内容；默认只存在内存，导出需玩家操作。
- **量化指标：** 1 Hz 采样、60 个样本加 32 个连接转换；内存不超过 256 KiB；每次采样 P95 小于 0.5 ms。
- **AT-D04-01（正常）：** 模拟平滑 RTT、丢包估计和心跳年龄逐步升高后原生
  Timeout；报告包含对应趋势和 Timeout 根因，不把 Ping 变化量谎称传输层 jitter，
  也不将问题归为 Mod。
- **AT-D04-02（异常）：** 平台统计接口抛错或返回缺失字段；快照标为部分不可用，连接流程不受影响，报告无端点信息。

## D5 报告历史

- **用户可观察行为：** 持久报告历史默认关闭。玩家可逐份“保存到历史”，或在看见
  保留期/容量/清除方法后明确开启自动保留；之后控制台列出脱敏报告并提供查看、
  复制、单项删除和全部清除。
- **成功标准：** 未授权时只保留本进程内有界报告且磁盘零文件；报告在任何持久化
  前完成脱敏；授权后按时间排序并在达到上限时原子删除最旧项。关闭自动保留必须
  同步停止新写入，既有历史是否删除由用户另行确认。
- **降级/失败行为：** 存储不可写时降级为本次进程内历史并提示；损坏条目被隔离，不阻止其余报告加载。
- **安全与隐私边界：** 只写 BetterCoop 自有目录；不保存原始日志、路径、摘要、账号、IP 或凭据；不上传、不自动打开外部程序。
- **量化指标：** 最多 20 份、单份 1 MiB、总计不超过 25 MiB、最长保留 30 天；
  任一边界先达到即淘汰最旧项；列表加载 P95 不超过 100 ms。
- **AT-D05-01（正常）：** 明确开启自动保留后生成 21 份合规报告；历史仅保留满足
  数量/总量边界的最新 20 份，顺序和错误编号正确，重启后仍可读取。
- **AT-D05-02（异常）：** 历史关闭时触发 100 次事故，用户目录报告文件数仍为 0；
  开启后再撤销时立即停止排队/新写入。损坏项或只读目录只使新报告留在内存，
  不改动其他文件或其他系统用户目录。

## D6 离线对比两份报告

- **用户可观察行为：** 玩家粘贴或选择两份 BetterCoop 报告后，本地显示版本、角色、时间线、网络、Mod/环境和错误分类的共同点与首个可观察分歧。
- **成功标准：** 只对兼容模式报告做结构化比较；“首个可观察分歧”与“根因”分开显示，并按证据给出三级置信度。
- **降级/失败行为：** 报告版本不兼容、会话 ID 不同、时间无法对齐或字段缺失时显示限制，不强行合并或归责。
- **安全与隐私边界：** 完全离线，不上传、不读取报告中引用的路径、不执行嵌入内容；输入按不可信文本限长解析。
- **量化指标：** 每份输入最大 1 MiB；两份报告比较 P95 不超过 100 ms；最多显示
  200 个差异并保留总数。
- **AT-D06-01（正常）：** 同一 D7 会话的主机/客户端报告在同一时间点出现不同连接状态；对比准确标出最早分歧，根因置信度不被夸大。
- **AT-D06-02（异常）：** 一份报告超限、模式未知或含伪造控制字符；安全拒绝或清理显示，不访问网络、不执行文本、不崩溃。

## D7 共享会话 ID

- **用户可观察行为：** 同一联机会话的所有玩家在控制台和报告中看到相同短会话 ID，用于人工配对报告；新大厅生成新 ID。
- **成功标准：** 主机使用密码学安全随机数生成 128 位会话 ID，经 G11 协商只接受当前已认证主机提供的固定格式；所有已加入玩家一致。
- **降级/失败行为：** ID 缺失、重复冲突、发送者无效或能力不兼容时显示“会话 ID 不可用”，D6 不自动配对。
- **安全与隐私边界：** 不从 Steam/lobby ID、玩家 ID、时间或存档派生；只用于当前大厅和玩家主动导出的报告，不用于跨会话追踪或遥测。
- **量化指标：** 原始随机强度 128 位；UI 短 ID 至少 50 位有效信息，完整报告保留全部 128 位；编码不超过 32 字节。
- **AT-D07-01（正常）：** 三名玩家加入同一大厅；三端短 ID 相同，退出重建大厅后 ID 改变。
- **AT-D07-02（异常）：** 非主机发送替代 ID 或同一会话收到两个主机 ID；拒绝替代值、标记会话 ID 无效，不用于报告合并。

## D8 下次启动原生崩溃复盘

- **用户可观察行为：** 若上次会话未完成干净关闭，下次启动显示“上次可能异常终止”，结合已有本地日志尾部给出错误签名、最后阶段和置信度。
- **成功标准：** 使用 BetterCoop 自有会话标记和有界日志尾部；只有明确原生崩溃签名可提高置信度，单纯 marker 残留为“证据不足”。
- **降级/失败行为：** 日志不存在、无法读取或 marker 损坏时只显示有限说明；正常退出必须清除 marker，且复盘失败不阻止启动。
- **安全与隐私边界：** 不安装外部守护进程、崩溃注入器或系统服务；不上传 dump；展示和复制前完成脱敏，且不修改游戏日志。
- **量化指标：** 启动最多读取上一份日志尾部 1 MiB；复盘 P95 不超过 250 ms；marker 不超过 1 KiB。
- **AT-D08-01（正常）：** 测试进程留下 marker 和明确 native crash 签名后退出；下次启动显示最后阶段、签名和适当置信度，随后开始新会话。
- **AT-D08-02（异常）：** 进程被任务管理器结束但无崩溃签名；只显示“异常终止/证据不足”，不宣称某 Mod 导致崩溃。

## D9 依赖感知 Mod 二分计划

- **用户可观察行为：** 玩家选择疑似 Mod 集合后，工具按 manifest 依赖闭包生成多轮手动 A/B 测试计划，显示每轮启用集合、必须保留的依赖和预期下一步。
- **成功标准：** 每个建议集合均满足已知必需依赖；依赖环作为不可拆分单元；计划明确要求新开局并记录每轮结果。
- **降级/失败行为：** manifest 损坏、依赖未知、候选不可拆分或基线本身无法启动时解释限制并停止生成不安全步骤。
- **安全与隐私边界：** 只生成和复制计划；不编辑设置、不启停/移动/删除 Mod、不启动游戏、不修改存档；测试结果不自动归责。
- **量化指标：** 对 N 个独立候选组，目标轮数不超过 `ceil(log2(N)) + 2`；256 个 Mod 的计划生成 P95 不超过 100 ms。
- **AT-D09-01（正常）：** 8 个独立候选加 2 个公共依赖；计划每轮保留必需依赖，并在不超过 5 轮的路径内隔离单组。
- **AT-D09-02（异常）：** 候选含依赖环、缺失依赖和损坏 manifest；环被成组处理，缺失项使计划停止或降级，不修改任何 Mod 设置。

## D10 主机诊断视图

- **用户可观察行为：** 主机只读面板按玩家显示连接/准备、G11 能力、D7 会话 ID、最后进度时间、D2 等待原因/置信度和 D4 网络摘要。
- **成功标准：** 数据标明来源和更新时间；超过新鲜度阈值显示 stale，不把无更新直接解释为掉线、软锁或恶意行为；玩家排序稳定。
- **降级/失败行为：** 某客户端缺少可选诊断能力或状态消息无效时仅该行显示不可用；
  Guard/包不兼容仍由独立原生 Mod-list 在加入前阻断，不由 G11 可选通道决定。
- **安全与隐私边界：** 不显示隐藏选择、手牌、牌组、种子、RNG、IP、Steam ID 或原始消息；没有强制准备、踢出、断线、状态修复或远程文件操作控件。
- **量化指标：** 最多 16 名玩家、每人状态不超过 2 KiB、更新频率不高于 1 Hz；5 秒无更新标 stale；每次刷新 P95 不超过 5 ms。
- **AT-D10-01（正常）：** 三名玩家中一人网络恶化、一人等待公开选择；主机面板分别显示网络趋势和已确认等待原因，不泄露选择内容。
- **AT-D10-02（异常）：** 客户端发送超限、乱序或带控制字符的状态；该状态被丢弃并标无效，其他玩家行正常，主机不能据此自动踢人或修改游戏。

## 完成判定

任一 G/D 项只有在其全部成功标准、量化指标、正常场景和异常场景均通过，且全局安全边界没有回归时，才可标记为完成。任何会自动改变其他 Mod、游戏状态、RNG 或存档的实现，无论功能测试结果如何，均判定该项验收失败。

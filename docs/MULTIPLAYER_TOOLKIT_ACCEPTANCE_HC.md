# Multiplayer Toolkit H/C 验收契约

状态：设计验收草案，不代表功能已经实现。
基线：Slay the Spire 2 `v0.109.1`；CoopGuard 的 Guard、指纹握手和故障说明仍是独立核心。

## 全局硬性边界

- H1-H12、C1-C10 全部属于可选工具层。任一功能缺失、关闭、协商失败、抛出异常或被游戏更新破坏，都不得削弱、阻塞或改变 Guard 的指纹计算、原生 Mod 列表握手、ready/begin 拦截和 fail-closed 行为。
- 工具层必须 fail-open：失败时移除或隐藏自身 UI、停止自身任务并记录一条有界本地日志；不得因此断开玩家、阻止开局或伪造 Guard 已验证状态。
- 工具层只能观察联机状态。不得取消、插入、重排或恢复行动，不得改写战斗、玩家、RNG、房间、run 或 save 状态，也不得尝试自动修复 StateDivergence。
- “未知”是合法结果。客户端只可把本机到主机的指标标为实测；主机才可把本机到各客户端的指标标为实测。没有数据时不得推断其他两名客户端之间的网络质量。
- 默认不持久化联机工具数据。不得上传遥测；不得在 UI、日志或复制报告中暴露 Steam ID、lobby ID、IP/端点、绝对路径、存档、凭据、完整包摘要或原始网络消息。
- 需要自定义消息的功能使用独立、版本化、限长的 Toolkit 能力协商。未知、畸形、超限或不兼容消息只禁用对应工具功能，不得影响 Guard 或原生联机。
- 工具层在关闭状态下不得发送自定义消息。本地只读功能在协议语义上不依赖远端
  工具能力；但当前产品与 `affects_gameplay: true` 的 Guard 共用一个 DLL，
  因此实际联机仍要求所有参与者按 STS2 原生 Mod-list 规则使用相同发布包。
- 除各项更严格预算外，工具层必须满足技术方案的全局 SLO：HUD 主线程开销
  `p95 ≤0.25 ms/frame`、`p99 ≤0.75 ms/frame`，稳态托管分配
  `≤10 KiB/s`，退出 run 后 `2 s` 内释放会话缓存和事件订阅。

## H1 网络 HUD

**用户可观察行为**

- 在联机界面显示本机视角的 RTT、估算丢包率、距最后心跳时间和远端加载状态。
- 每个数字明确标记“本机→主机”或“主机→该玩家”；不可观测的链路显示“未知”，不显示假 `0 ms`。

**成功标准**

- 数值直接来自 `INetGameService.GetStatsForPeer()` 返回的 `ConnectionStats`，不额外发送探测包。
- 与原生网络问题图标、3 秒普通无响应阈值和 8 秒远端加载阈值含义一致。

**降级/失败行为**

- 服务、peer 或统计对象不存在时，该行显示“等待数据/未知”并继续游戏。
- HUD 创建或刷新失败时只隐藏 H1；Guard、原生超时遮罩和错误弹窗继续工作。

**安全与隐私边界**

- 不显示或记录 peer ID、端点、lobby ID；复制诊断时仅保留角色化匿名标签。
- 客户端不得把主机对其他客户端的情况伪装成本机实测数据。

**性能与时效**

- 采样频率不高于 `1 Hz`；新样本应在 `250 ms` 内显示。
- 单次刷新预算 `≤1 ms`，稳态缓存 `≤4 KiB/peer`。

**验收场景**

- `AT-H01-01`（正常）：两客户端 RTT 分别稳定在约 40 ms 和 180 ms 时，主机 HUD 在 2 秒内显示两条独立实测值，误差不超过底层 `ConnectionStats` 的一个采样周期。
- `AT-H01-02`（异常）：客户端查询一个没有统计对象的队友时显示“未知”，不出现 `0 ms`，不发送额外消息且仍可 ready/开局。

## H2 “正在等什么”

**用户可观察行为**

- 用一条可解释状态说明当前主要等待原因：玩家未结束回合、远端加载、网络无响应、原生行动执行中、玩家选择中、阶段同步中或未知。
- 能可靠识别玩家时显示公开昵称/角色；证据不足时只显示类别，不猜责任玩家或 Mod。

**成功标准**

- 依据 `CombatManager.IsPlayerReadyToEndTurn()`、`RunLobby.ConnectedPlayerIds`、`ActionQueueSynchronizer.CombatState`、`ActionExecutor.CurrentlyRunningAction` 和网络统计按固定优先级分类。
- 精确选择等待者只可来自已审计
  `PlayerChoiceSynchronizer.WaitForRemoteChoice(...)` 的只读
  prefix/finalizer 观察，标记 `NativeObserved/High`；不得主动调用方法、读取会
  消费队列的 API 或标成主机权威根因。
- 原因变化后旧计时和旧标签同时结束，不残留上一阶段信息。

**降级/失败行为**

- 私有队列内容不可用、事件丢失或状态组合无法解释时显示“等待游戏继续（原因未知）”。
- H2 绝不调用 unpause、cancel、resume、enqueue 或 disconnect。

**安全与隐私边界**

- 不显示隐藏手牌、选择内容、随机结果或 `GameAction.ToString()` 中未经审查的字段。
- “可能软锁”必须与“已确认错误”分开；仅时间经过不能证明软锁。

**性能与时效**

- 原生事件触发后的状态更新 `≤250 ms`；兜底轮询间隔 `≥500 ms`。
- 同一原因稳定少于 `10 s` 时不得发出软锁警报。

**验收场景**

- `AT-H02-01`（正常）：三人战斗中两人已结束回合、一人未结束时，250 ms 内显示
  “等待该玩家结束回合”；选择 fixture 中只有 prefix 已进入且 finalizer 未完成时
  才以 High 显示等待者，Hook 缺失则为 Unknown；该玩家结束后标签切换。
- `AT-H02-02`（异常）：行动动画持续 12 秒但 `CurrentlyRunningAction` 仍在推进时只显示“行动执行中”，不得宣称某玩家掉线或自动干预队列。

## H3 大厅健康矩阵

**用户可观察行为**

- 大厅按玩家列出连接、Toolkit 能力、Guard/环境校验结果、ready 状态和可观测网络健康。
- 每格使用“通过/失败/未知/不支持”，不把“未报告”显示为“通过”。

**成功标准**

- 本地 Guard 状态来自现有验证结果；主机对远端只能显示“原生握手匹配（主机推断）”
  或“peer 自报”，并附来源/时间，不能写成“主机权威验证了远端本地检查”。
- 到达大厅不等于永久健康；本地包发生变化后，本机行立即撤销通过状态。

**降级/失败行为**

- 同一 CoopGuard 发布包中本地关闭 Toolkit、平台 API 不可用或模块初始化失败的
  玩家显示“Toolkit 不可用”，大厅与 Guard 仍按原规则运行。真正不同发布包会在
  进入大厅前被严格 Guard 拒绝，不属于 H3 降级场景。
- 合并 keepalive 每 2 秒一次；连续漏掉两个周期并经过 1 秒容差（总计 `5 s`）
  后显示“未知/stale”，不得踢人或阻止 ready。

**安全与隐私边界**

- 矩阵只显示状态和会话内昵称，不显示摘要、文件数差异、路径或账户标识。
- 该矩阵不是远程证明或反作弊；UI 必须提供此说明。

**性能与时效**

- 状态变化 `≤500 ms` 可见；支持至少 8 行且一次刷新 `≤2 ms`。
- 每名玩家状态字段 `≤256 B`，仅变化时进入共享调度器；不得建立 H3 专用保活，
  空闲合并 keepalive 为每 `2 s` 一次。

**验收场景**

- `AT-H03-01`（正常）：8 人使用同一发布包，其中 7 人模块健康、1 人本地关闭
  Toolkit；矩阵准确显示 7 个状态和 1 个“本地关闭”，远端 Guard 单元格标明
  “由握手推断”，所有人仍只由原生/Guard 规则决定是否开局。
- `AT-H03-02`（异常）：收到超长或未知版本健康消息时只把发送者 Toolkit 单元格降为“不可用”，Guard 握手结果和大厅连接保持不变。

## H4 加入阶段进度

**用户可观察行为**

- 加入时显示离散阶段：连接平台、等待 InitialGameInfo、校验版本/分支/Mod/ModelDb、
  等待新局大厅响应或读档大厅响应。
- 在 v0.109.1 收到 `RunSessionState.Running` 时，阶段必须结束为
  `RunInProgress / Unsupported`；只有未来构建通过 C6-P6 能力门禁后，才允许
  出现“等待运行中快照/恢复完成”。
- 显示本阶段已用时间，不显示无法证明的百分比。

**成功标准**

- 阶段由 `JoinFlow.Begin` 及对应响应入口产生；成功后在进入目标场景前显示完成。
- 失败弹窗包含最后一个已进入阶段和该阶段耗时。

**降级/失败行为**

- 游戏更新导致阶段 Hook 缺失时退化为“正在加入”，原生连接和 Guard 继续执行。
- 阶段 UI 不得延长或替换原生十秒握手超时。

**安全与隐私边界**

- 不显示 initializer 的 `ToString()`，因为其中可能含 player/lobby ID。
- 不记录主机地址、邀请来源或原始消息内容。

**性能与时效**

- 阶段转换后 `≤100 ms` 更新；计时显示精度 `±250 ms`。
- 不增加网络往返，不创建短于 `250 ms` 的刷新循环。

**验收场景**

- `AT-H04-01`（正常）：加入 loaded pre-run lobby 时依次看到连接、初始信息校验、
  等待读档大厅响应、完成；对 v0.109.1 running 房间则依次到
  `RunInProgress / Unsupported` 并结束，绝不显示等待快照或完成。
- `AT-H04-02`（异常）：InitialGameInfo 超时后弹窗标明“等待初始信息”及耗时；若 H4 Hook 故障，原生超时仍在原期限内发生。

## H5 联机事件时间线

**用户可观察行为**

- 会话内时间线记录加入、离开、rejoin、ready、加载开始/结束、网络警报、同步检查点和错误分类。
- 每项带相对时间、角色化玩家标签、严重性和证据来源。

**成功标准**

- 事件由游戏公开事件或已验证 Hook 产生，按单调时钟排序；重复状态在 `1 s` 内合并。
- 打开时间线不暂停游戏，关闭后继续收集会话内有界事件。

**降级/失败行为**

- 缺少来源时省略该事件，不从日志字符串猜造玩家或阶段。
- D3 达到统一上限时按其规则淘汰；H5 不自行保留或删除事件。H5 渲染故障不影响
  D3、H12、Guard 或原生 UI。

**安全与隐私边界**

- 默认仅内存保存；退出 run 后清空。
- 复制内容使用“玩家 1/2”等匿名标签，删除 Steam/lobby/端点/路径/摘要。

**性能与时效**

- H5 最多渲染 D3 唯一环中的最近 `100` 项，不另建存储；新事件 `≤250 ms` 出现。
- 合并后平均分配 `≤64 KiB/min`，单次渲染 `≤2 ms`。

**验收场景**

- `AT-H05-01`（正常）：玩家掉线后 15 秒 rejoin，时间线顺序显示掉线、等待、重新加入，时间误差不超过 500 ms。
- `AT-H05-02`（异常）：每帧重复同一网络警告 10 秒时，D3 合并为一项并增加计数，
  H5 不另建缓冲、不增长到 100 项，也不写磁盘。

## H6 选择进度

**用户可观察行为**

- 显示有多少玩家正处于必须完成的原生选择、多少已完成，以及当前是否因此阻塞推进。
- 只在游戏已经公开“玩家正在选择”时标识玩家，不显示具体选项或选择结果。

**成功标准**

- 本地玩家进度来自自己的公开选择状态；远端只来自
  `WaitForRemoteChoice` 的已审计只读观察或可选 peer 声明。两者都不可用时人数
  为 Unknown，不从私有队列/完整状态猜测；离开选择界面后对应状态清除。
- 显示人数与当前 run 玩家集合一致，断线玩家另标“断线”而非“选择中”。

**降级/失败行为**

- 无法可靠识别选择拥有者时仅显示“有选择尚未完成”，人数显示未知。
- 不得通过检查私有手牌、奖励内容或序列化状态来补齐信息。

**安全与隐私边界**

- 禁止显示卡牌、遗物、药水、路径、事件选项或任何尚未由游戏公开的决定。
- 不发送新的选择确认或替玩家提交选择。

**性能与时效**

- 选择开始/完成后 `≤250 ms` 更新；无事件时轮询不高于 `2 Hz`。
- 状态缓存 `≤1 KiB/player`。

**验收场景**

- `AT-H06-01`（正常）：四人同时获得公开奖励选择，三人完成后显示 `3/4`，最后一人完成后 250 ms 内清零。
- `AT-H06-02`（异常）：无法访问某 Mod 的自定义选择类型时显示“选择状态未知”，不读取或展示其选项，也不阻塞行动队列。

## H7 紧凑公开队友状态

**用户可观察行为**

- 每名队友以紧凑行显示公开昵称/角色、连接、ready/回合完成、加载、网络警告和当前公开阶段。
- 默认收起详细数值；展开时复用 H1/H2，不重复创建独立状态源。

**成功标准**

- 与原生 `NMultiplayerPlayerState` 的断线、网络问题和回合结束状态一致。
- 玩家 rejoin 后复用原会话身份行，不产生重复玩家。

**降级/失败行为**

- 屏幕空间不足时变为可滚动或只保留图标+文本标签，不遮挡结束回合、手牌和目标选择。
- 单个玩家状态刷新异常只将该行标为未知。

**安全与隐私边界**

- 仅展示游戏已公开的信息；不增加窥视手牌、牌堆、金币细节或悬停目标的能力。
- 原始 NetId 只可用于会话内关联，不得显示、持久化或复制。

**性能与时效**

- 状态事件 `≤250 ms` 可见；8 人列表全量刷新 `≤2 ms`。
- 静止时不得每帧重排节点。

**验收场景**

- `AT-H07-01`（正常）：8 人局中一人加载、一人掉线、两人已结束回合时，各行在 500 ms 内显示互不冲突的状态。
- `AT-H07-02`（异常）：分辨率不足以容纳 8 行时列表滚动且不覆盖原生按钮；关闭 H7 后原生玩家状态仍正常。

## H8 近 60 秒网络图

**用户可观察行为**

- 按本机可观测 peer 绘制最近 60 秒 RTT、丢包和无响应区段；加载区段有独立底纹。
- 图例说明数据是平滑估计值，不是 Steam 原始链路抓包。

**成功标准**

- 复用 H1 样本，断线/无样本用空洞表示，不用上一个值无限延长。
- 时间轴使用单调时钟，暂停菜单或系统时间变化不倒退。

**降级/失败行为**

- 少于两个有效样本时显示“数据不足”；图表渲染失败时保留 H1 文本指标。
- 客户端仅绘制到主机的图，不虚构队友间曲线。

**安全与隐私边界**

- 图数据仅保留内存，不包含 peer ID、IP 或 lobby ID，默认不进入复制报告。
- 不调用 SteamNetworking 的低层抓包或额外统计接口。

**性能与时效**

- `1 Hz`、每 peer 恰好最多 `60` 个样本；内存 `≤16 KiB/peer`。
- 重绘频率不高于 `2 Hz`，单次重绘 `≤2 ms`。

**验收场景**

- `AT-H08-01`（正常）：注入 60 秒阶梯 RTT 和 10 秒远端加载状态后，图中样本数、峰值和加载区间与源数据一致。
- `AT-H08-02`（异常）：连续 8 秒无心跳时图中形成空洞/无响应段，不画成 `0 ms`，原生超时流程不被延迟。

## H9 共享环境短码

**用户可观察行为**

- 在同一会话为已验证的游戏版本、Guard 协议和有效包指纹显示短码，便于语音快速人工比对。
- UI 明示“短码仅供排查，不能替代 Guard 完整握手”。

**成功标准**

- 短码由会话随机 nonce 与完整环境元组经 SHA-256 派生，再取 10 个 Base32 字符；相同环境与 nonce 得到相同码。
- nonce 至少 128 bit，由主机 Toolkit 生成；无协商能力时短码显示“不可用”，不得改用长期稳定的裸摘要短码。

**降级/失败行为**

- 任一输入无效、指纹失败、同包模块不可用或防御性协议检查失败时不生成短码；
  真正不同发布包由 Guard 在进入 lobby 前拒绝。
- 短码相同或不同都不得直接允许/拒绝 ready；Guard 独立作最终决定。

**安全与隐私边界**

- nonce 和短码只存在当前会话，不写日志、不复制、不跨会话复用。
- 不传输原始摘要、文件清单、路径、设置或存档。

**性能与时效**

- 每次环境变化最多重算一次，计算 `≤100 ms`；消息 `≤64 B`。
- 不定时广播；新玩家加入时最多补发一次 nonce。

**验收场景**

- `AT-H09-01`（正常）：三名玩家环境相同且收到同一 nonce 时在 500 ms 内显示相同 10 字符短码。
- `AT-H09-02`（异常）：一名玩家不支持 Toolkit 或 nonce 消息畸形时显示“不可用”，不降级为稳定指纹码，也不影响 Guard 拒绝/允许逻辑。

## H10 加载速度/进度

**用户可观察行为**

- 显示本地加载已用时间和本机可观测远端的“加载中/已响应/未知”；完成后可显示本次加载耗时。
- 没有原生百分比时绝不显示伪造百分比或估算剩余秒数。

**成功标准**

- 远端状态来自 `ConnectionStats.RemoteIsLoading`；本地状态来自原生 loading handle/场景事件。
- 加载结束后计时停止，下一次加载使用新记录。

**降级/失败行为**

- 客户端无法看到其他客户端加载状态时明确显示“不可观测”；可选 Toolkit 未协商时不补猜。
- 丢失结束事件时在 run 场景稳定或会话结束时自动关闭计时，不永久显示加载中。

**安全与隐私边界**

- 不枚举资源路径、磁盘速度、硬件型号或其他玩家设备信息。
- 加载时长默认仅本地；共享时只传布尔状态和开始/结束时刻差值。

**性能与时效**

- 显示刷新不高于 `4 Hz`、计时精度 `±250 ms`；状态改变 `≤500 ms` 可见。
- 每次加载仅保留一个当前值和最近 5 次本地耗时。

**验收场景**

- `AT-H10-01`（正常）：主机观察客户端加载 4 秒，状态先显示“加载中”后显示约 4 秒完成耗时，误差不超过 500 ms。
- `AT-H10-02`（异常）：客户端只可观测主机时，其他队友显示“不可观测”而非百分比；H10 关闭不改变 `SetGameLoading`。

## H11 玩家身份颜色

**用户可观察行为**

- 同一玩家在 HUD、时间线、提示和图表中使用一致的颜色、编号和图形标记。
- 颜色相近时仍可通过“P1/P2…”和形状识别，信息不只依赖颜色。

**成功标准**

- 映射在当前会话和 rejoin 前后稳定；新会话重新生成。
- 文本与背景满足至少 `4.5:1` 对比度，非文本边界至少 `3:1`。

**降级/失败行为**

- 色板耗尽或角色原生颜色冲突时复用颜色但分配不同编号/形状。
- 无法获得玩家映射时显示中性颜色和“未知玩家”，不暴露 NetId。

**安全与隐私边界**

- 映射只以会话内玩家键关联，不持久化 Steam ID，不用于跨局追踪。
- 不改变游戏原生角色、地图绘制或卡牌视觉颜色。

**性能与时效**

- 玩家加入/rejoin 后 `≤250 ms` 应用；映射查找 `O(1)`。
- 最多缓存当前 run 玩家数，不保留历史会话映射。

**验收场景**

- `AT-H11-01`（正常）：玩家掉线并 rejoin 后在所有工具 UI 保持原颜色、编号和形状。
- `AT-H11-02`（异常）：12 名玩家超过基础色板时仍能靠编号/形状唯一识别，且没有显示任何原始账户 ID。

## H12 警报中心

**用户可观察行为**

- 汇总网络恶化、等待过久、玩家掉线/rejoin、Toolkit 降级和 Guard/原生错误；分为信息、警告、致命。
- 警报可确认但不自动消除仍在发生的条件；点击可跳到相关 H1/H2/H5 信息。

**成功标准**

- 相同来源和类型在 `5 s` 窗口内去重；致命错误优先于普通网络波动。
- Guard 产生的阻断仅镜像展示，H12 不重新判断或覆盖结果。

**降级/失败行为**

- 警报中心不可用时原生弹窗、Guard 弹窗和日志仍照常出现。
- 达到上限时先丢弃已确认的信息级项目，不丢弃当前致命项目。

**安全与隐私边界**

- 最多保留当前会话 50 项，退出后清空；复制时沿用既有严格脱敏。
- 不根据告警频率自动踢人、禁用 Mod、重连或修改存档。

**性能与时效**

- 事件发生后 `≤250 ms` 入列；去重查找和渲染单次 `≤2 ms`。
- 声音交给 C7，H12 自身不重复播放。

**验收场景**

- `AT-H12-01`（正常）：同一 peer 丢包警告重复 20 次只生成一个带计数的警报，掉线时升级为更高严重性。
- `AT-H12-02`（异常）：H12 UI 构造抛异常时自动禁用并释放订阅；原生 StateDivergence/Guard mismatch 弹窗仍显示。

## C1 快捷状态消息

**用户可观察行为**

- 玩家可发送固定短语，如“稍等”“可以开始”“正在选择”“需要重连”“看地图”，并看到发送者身份标记。
- 不提供任意文本输入；消息可静音。

**成功标准**

- 消息使用版本化枚举和本地化键传输，未知枚举显示“未知状态”或丢弃。
- 仅在所有接收端确认支持时启用发送按钮。

**降级/失败行为**

- 不支持 Toolkit 的会话中按钮隐藏；消息发送失败只给本地提示。
- 达到速率限制时本地拒绝并提示冷却，不断开玩家。

**安全与隐私边界**

- 不包含自由文本、路径、账户 ID 或游戏隐藏状态。
- 接收端可按玩家或全局静音；静音只影响 C1/C7，不影响 Guard。

**性能与时效**

- 单条载荷 `≤64 B`；每玩家最多 `1 条/s`、突发 3 条，随后至少 3 秒冷却，且
  必须与所有其他功能共用总体 `1 envelope/s`、burst 4 的调度器。
- 正常链路下 `≤500 ms` 显示。

**验收场景**

- `AT-C01-01`（正常）：发送“稍等”后所有支持端在 500 ms 内以各自语言显示同一语义和正确玩家标记。
- `AT-C01-02`（异常）：连续发送第 4 条突发消息时本地限流，不产生网络包，不影响 ready 或 Guard。

## C2 地图选择进度

**用户可观察行为**

- 显示已提交地图选择的人数和未提交的公开玩家列表；原生决定公布后显示最终节点。
- 决定公布前不显示每个人具体投向哪条路线。

**成功标准**

- 依据 `MapSelectionSynchronizer` 的公开投票/取消/决议事件维护状态。
- 进入新地图节点或取消选择时完整重置。

**降级/失败行为**

- Mod 自定义地图流程没有公开事件时只显示“地图选择进行中/未知”。
- C2 状态不参与计算胜出路线，也不发送替代投票。

**安全与隐私边界**

- 不提前暴露个人路线偏好、地图 RNG、未公开节点内容或鼠标悬停。
- 仅共享提交布尔值；最终选择以游戏原生结果为准。

**性能与时效**

- 投票/撤销后 `≤250 ms` 更新；单次状态消息 `≤128 B`。
- 同一玩家相同状态不重复广播。

**验收场景**

- `AT-C02-01`（正常）：四人中三人提交时显示 `3/4` 和一名待提交玩家；决议后只显示原生最终节点。
- `AT-C02-02`（异常）：收到重复或乱序提交状态时按单调序号忽略旧值，不提前显示具体路线，不影响原生投票。

## C3 公开行动流

**用户可观察行为**

- 显示最近已被游戏接受并开始/完成执行的公开行动类别、拥有者和状态。
- 默认只显示“出牌/使用药水/结束回合/系统效果”等白名单类别，不展示对象的完整字符串。

**成功标准**

- 来源为 `ActionExecutor.BeforeActionExecuted/AfterActionExecuted` 及公开行动事件。
- 同一行动以 ID 更新一行，不因开始/完成生成重复行。

**降级/失败行为**

- 未知或 Mod 自定义行动显示“自定义行动”，不反射其字段。
- 事件遗漏时允许时间线缺项，不扫描私有队列补齐。

**安全与隐私边界**

- 禁止展示尚未执行的排队意图、隐藏手牌、选择内容、目标预览、RNG 或序列化参数。
- C3 只观察，不调用 enqueue/cancel/resume。

**性能与时效**

- 最多显示最近 8 项，完成项 15 秒后淡出；事件 `≤100 ms` 可见。
- 单次更新 `≤1 ms`，无每帧队列扫描。

**验收场景**

- `AT-C03-01`（正常）：公开 PlayCardAction 开始并完成时同一行从“执行中”变为“完成”，玩家和类别正确。
- `AT-C03-02`（异常）：自定义行动的 `ToString()` 含路径和卡牌名时 UI 只显示“自定义行动”，敏感文本未进入日志或复制内容。

## C4 等待计时器

**用户可观察行为**

- 对 H2 当前稳定原因显示已等待时长；原因变化即归零。
- 超过当前发布版固定且经过测试的提示阈值时变色，但仍使用“等待过久/可能异常”，
  不宣称已死锁。只有形成真实用户需求和完整阈值矩阵后才增加用户配置。

**成功标准**

- 使用单调时钟；菜单暂停、系统时钟调整和帧率变化不造成倒退或跳变。
- 只在原因稳定 `500 ms` 后启动，避免阶段瞬态闪烁。

**降级/失败行为**

- H2 原因未知时可计时但标为“未知等待”；H2 不可用时 C4 隐藏。
- 计时器到阈值只产生 H12 警告，不执行恢复动作。

**安全与隐私边界**

- 不以等待时长给玩家评分、自动踢人或推断硬件/网络责任。
- 不持久化个人等待历史。

**性能与时效**

- 显示更新不高于 `4 Hz`，误差 `≤250 ms`。
- 默认提示阈值 `15 s`，同一原因每 `60 s` 最多再次提醒一次。

**验收场景**

- `AT-C04-01`（正常）：等待玩家结束回合 6 秒后计时显示约 6 秒；进入敌方回合后 250 ms 内归零/隐藏。
- `AT-C04-02`（异常）：系统时钟向后调整一分钟时计时仍单调增长，不产生负数或自动恢复队列。

## C5 重连状态卡

**用户可观察行为**

- 显示“已断线、可重进大厅、连接平台、等待初始信息、验证环境、恢复大厅、
  运行中恢复不受本体支持、失败”之一及阶段耗时。只有未来已审计构建才增加
  “接收快照/恢复运行”阶段。
- 对 StateDivergence、ModMismatch、HostAbandoned 等不安全/无意义原因明确显示“不建议快速重连”。

**成功标准**

- 状态来自原生 disconnect reason、H4 阶段和 JoinFlow 结果；v0.109.1 仅在
  `InLobby`/`InLoadedLobby` 恢复且原生服务已连接后显示完成。`Running` 必须
  显示 `RunInProgress / Unsupported`，不能把协议数据结构当作恢复能力。
- 卡片提供复制脱敏诊断和 C6 用户按钮，但自身不发起连接。

**降级/失败行为**

- 无 lobby 标识、非 Steam 后端或主机已结束时只提供原生返回流程。
- 状态 Hook 故障时显示“重连状态未知”，不猜测成功。

**安全与隐私边界**

- lobby ticket 必须在仍连接、原生清空 `_lobbyId` 之前复制；仅内存、一次性、
  TTL `≤10 min`，UI/日志/剪贴板中不显示。成功、过期、会话/房主变化或不安全
  原因立即清除。
- 不承诺 rejoin 能修复已分叉状态；此警告必须可见。

**性能与时效**

- 阶段变化 `≤250 ms` 可见；断线后 `≤1 s` 给出资格判断。
- 单次只允许一个进行中的重连状态机。

**验收场景**

- `AT-C05-01`（正常）：pre-run lobby 的 Timeout 返回主菜单后 1 秒内显示
  “可重进大厅”，用户执行 C6 后阶段依次更新并最终恢复到同一 lobby。
- `AT-C05-02`（异常）：运行中 Timeout 在 v0.109.1 显示“本体不支持运行中恢复”；
  StateDivergence 同样无 C6 按钮。两者都不尝试恢复战斗或改变存档。

## C6 仅用户点击的原生一键重连

**用户可观察行为**

- 仅在 C5 判断当前构建和 session state 支持时显示按钮；每次点击只发起一次原生
  Steam lobby 加入。v0.109.1 的 `Running` 状态不显示按钮。
- 失败后显示原生原因和诊断，可由用户在冷却后再次点击。

**成功标准**

- 使用断线前缓存的一次性 lobby ticket、
  `SteamClientConnectionInitializer.FromLobby()` 和原生主菜单 `JoinGame()`；
  当前基线只承诺 `InLobby`/`InLoadedLobby`。
- 点击前重新执行本地 Guard 验证；验证失败时由 Guard 按原规则阻断。

**降级/失败行为**

- 非 Steam、无/过期 ticket、`Running`、主机角色、已有连接尝试或不安全断线
  原因时按钮禁用/隐藏。
- 场景转换、初始化器或 JoinGame 失败时回到主菜单，不循环重试、不终止进程。

**安全与隐私边界**

- 严禁自动点击、后台重连、无限重试或绕过原生/Guard 校验。
- 不保存 lobby ID 到磁盘，不通过自定义消息转发邀请。

**性能与时效**

- 点击后 `≤100 ms` 进入“正在重连”；每次只允许 1 个任务。
- 失败后至少 `5 s` 冷却；永远 `0` 次自动重试。

**验收场景**

- `AT-C06-01`（正常）：合法 pre-run lobby Timeout 后单击一次，恰好创建一个
  原生连接初始化器并恢复 lobby；ticket 随即失效。
- `AT-C06-02`（异常）：用户连续点击 10 次只产生一次连接尝试；ticket 过期、
  ModFingerprint 已变或状态为 `Running` 时不发起连接，Guard 不被绕过且自动
  重试次数为 0。
- `AT-C06-03`（未来能力门禁）：只有新 STS2 构建存在已审计生产恢复消费者并通过
  真实双客户端“断线—原生快照—同一 run 恢复”测试后，才允许对 `Running`
  显示按钮；否则测试结果必须是 Unsupported，不得用 CoopGuard 状态修复替代。

## C7 声音提示

**用户可观察行为**

- 可为全员 ready、等待本人操作、网络中断、玩家 rejoin 和重连结果播放不同短提示。
- 设置提供总开关、音量、每类开关，并配有等价视觉文字。

**成功标准**

- 复用游戏现有音频系统和用户主/SFX 音量；关闭或静音后不创建播放实例。
- 相同事件去重，不把 H1 每次网络样本变成声音。

**降级/失败行为**

- 音频资源或总线不可用时静默降级，H12 视觉警报继续。
- 后台/失焦策略遵从游戏设置，不强制抢占系统音频。

**安全与隐私边界**

- 不录音、不访问麦克风、不上传音频；声音不包含玩家提供的自由文本。
- 所有关键声音均有文字/图标等价项。

**性能与时效**

- 事件到播放 `≤250 ms`；同类提示至少间隔 `2 s`，所有提示最多 `3 次/10 s`。
- 单个提示 `≤2 s`，同时最多一个 Toolkit 提示。

**验收场景**

- `AT-C07-01`（正常）：最后一名玩家 ready 后 250 ms 内播放一次提示并同时显示文字。
- `AT-C07-02`（异常）：网络状态每秒抖动 20 次时 10 秒内最多播放 3 次；总开关关闭时播放数为 0。

## C8 无障碍

**用户可观察行为**

- H/C UI 支持键盘/手柄焦点、200% UI 缩放、减少动态效果、高对比文本，并为颜色和声音提供文字/形状替代。
- 焦点顺序与视觉顺序一致，关闭工具面板后焦点返回原控件。

**成功标准**

- 所有可操作控件无鼠标也能到达和激活；警报不会无故夺取焦点。
- 正文对比度至少 `4.5:1`，大字和非文本边界至少 `3:1`；状态不只靠红绿。

**降级/失败行为**

- 平台不提供屏幕阅读接口时文档明确“不保证系统屏幕阅读器”，但仍提供可复制文本和完整标签。
- 动画创建失败或减少动态开启时使用瞬时显隐，不丢状态。

**安全与隐私边界**

- 辅助文本遵守相同脱敏规则，不在 tooltip/accessible name 中藏入 ID、路径或摘要。
- 无障碍设置只存本地偏好，不与 peers 交换。

**性能与时效**

- 200% 缩放、1280×720 下无不可达控件和关键文字裁切。
- 焦点响应 `≤100 ms`；减少动态模式过渡动画 `≤100 ms`。

**验收场景**

- `AT-C08-01`（正常）：仅用键盘打开 HUD、浏览 8 名玩家、确认警报并关闭，焦点返回游戏原按钮；200% 下内容可滚动。
- `AT-C08-02`（异常）：使用红绿色觉缺陷模拟时仍可凭图标、编号和文字区分正常/警告；关闭声音后所有事件仍有视觉等价项。

## C9 精确手牌共享

**用户可观察行为**

- 默认关闭。仅当当前会话所有玩家逐一明确同意时，显示每名同意玩家当前手牌的卡牌身份、升级状态和当前公开费用。
- UI 始终显示“手牌共享中”，任何玩家可立即撤回同意。

**成功标准**

- 每次新会话、新玩家加入或玩家 rejoin 后重新取得全员一致同意；缺一票即全局关闭。
- 同意绑定 `{session_id, membership_epoch, exact_roster_digest}`；只有主机收齐
  OptIn、全员确认同一 Commit，且主机发布 Active 后才允许发送。只在本地手牌
  实际变化时发送版本化快照；接收端按 epoch 和单调序号拒绝旧快照。

**降级/失败行为**

- 本地撤回或原生成员变化 callback 必须同步关闭发送并立即清空缓存；远端状态
  `1 s` 内收敛。任何旧 session/epoch/roster 消息必须在字段解码和缓存前丢弃。
- 未知卡牌/字段显示“未知卡牌”；畸形、超限消息仅关闭 C9，不影响 Guard 或 run。

**安全与隐私边界**

- 这是主动泄露隐藏战斗信息的高风险功能，必须默认关闭、逐会话全员同意，不能以订阅 Mod 视为同意。
- 只允许卡牌模型 ID、升级状态和当前费用；禁止实例内部字段、抽牌堆顺序、RNG、选择候选、存档或账户数据。
- 不写磁盘、不写普通日志、不进入诊断剪贴板；退出/撤回后清零缓存。
- 列表只有一层重复记录；解析器必须在分配数组/字符串前验证 count `≤64`、
  单 ID `≤48 UTF-8 bytes`、remaining bytes 和 4 KiB 累计上限。

**性能与时效**

- 单玩家最多 64 张手牌、单快照 `≤4 KiB`；每玩家最多 `2 次/s`，只发变化触发的
  完整有界快照；该频率只能使用共享调度器 burst，总体仍不超过其令牌桶。超过
  任一边界时关闭该玩家的 C9 显示，不拆分成无界消息。
- 正常链路手牌变化 `≤500 ms` 可见；撤回清除 `≤1 s`。

**验收场景**

- `AT-C09-01`（正常）：三名玩家本会话全部明确同意后共享开启；一人抽牌时另外两端 500 ms 内准确显示身份、升级和费用。
- `AT-C09-02`（异常）：枚举“新玩家加入/rejoin/撤回”与旧手牌更新的全部关键乱序
  组合；发送端同步停止，失效 epoch 在解码前丢弃，所有端 1 秒内隐藏并清空。
  `uint32.MaxValue` count 不产生按 count 分配，日志/诊断找不到卡牌列表，Guard
  继续正常。

## C10 可选贡献统计

**用户可观察行为**

- 默认关闭；开启后显示会话内、定义明确的公开统计，例如造成伤害、给予他人防御/治疗、击杀和已完成行动数。
- 每个指标可查看定义，并标记“娱乐统计，不代表责任或技术健康”。

**成功标准**

- 只从游戏已执行完成的公开行动/效果事件累计；同一事件以稳定会话 ID 去重。
- 开关只影响显示/可选共享，不改变伤害、奖励、分数、成就或匹配。

**降级/失败行为**

- 无法可靠归属的效果进入“不归属”而非猜给最近行动者。
- Mod 自定义效果没有公开归属时忽略；计数器溢出、乱序或协议不兼容只重置/关闭 C10。

**安全与隐私边界**

- 不统计手牌内容、选择速度、失误、离线历史、等待责任或私人资源；不得用于自动踢人。
- 默认仅内存、仅当前会话；共享需单独开启，复制时匿名化玩家且不含账户 ID。

**性能与时效**

- 每玩家最多 10 个 64-bit 计数器，缓存 `≤8 KiB/player`；显示更新不高于 `1 Hz`。
- 共享摘要 `≤512 B/player`、最多每 `5 s` 一次；退出 run 后 `2 s` 内清空。

**验收场景**

- `AT-C10-01`（正常）：公开且可归属的伤害、防御和治疗事件各执行一次后，对应玩家计数只增加一次，1 秒内显示。
- `AT-C10-02`（异常）：同一事件重复通知或自定义效果无所有者时不重复、不猜测归属；关闭 C10 后无消息、无持久化，Guard 行为不变。

## 退出准则

某项只有在其全部成功标准、两类验收场景和全局边界同时通过后，才可标为“可发布”。任何测试若发现工具层能够绕过 Guard、改变游戏权威状态、暴露被禁止数据或把未知状态伪装成确定结论，该项直接判定失败，不允许以 UI 功能正常作为豁免。
